# 定时任务（Cron Jobs）

线上 Hermes Agent 运行两个定时任务，覆盖 TikTok Shop 达人合作的核心流程。

---

## 任务总览

| 任务 | 频率 | 单次上限 | 工具链 | 用途 |
|---|---|---|---|---|
| 样品审核 | 每天 9:30 | 50 条申请 | `tk_sample_requests` -> `tk_creator_detail` -> `tk_score_creator` -> `tk_send_feishu_card` | 拉取样品申请 -> 拉达人详情 -> DeepSeek 评分 -> S/A 级发飞书卡片 |
| IM 未回复自动回复 | 每 1 小时 | 30 个会话 | `tk_im_messages` (auto_reply=true) | 抓取 Not replied 会话消息 -> DeepSeek 生成回复 -> 发送到 TK IM -> 入库去重 |

---

## 1. 样品审核定时任务

### 触发频率
每天 9:30 运行一次。

### 流程

```
tk_sample_requests  ──->  tk_creator_detail  ──->  tk_score_creator  ──->  tk_send_feishu_card
  (拉申请50条)           (拉详情+7天缓存)         (DeepSeek 85分制评分)     (S/A级发飞书卡片)
```

### 参数

| 步骤 | 工具 | 关键参数 | 说明 |
|---|---|---|---|
| 1 | `tk_sample_requests` | `status=to_review, limit=50` | 拉取待审核样品申请，UPSERT 到 `sample_requests` 表 |
| 2 | `tk_creator_detail` | 对每个 `creator_oec_id` 调用 | 拉达人详情，7 天缓存（`creators` 表），`force_refresh` 可绕过 |
| 3 | `tk_score_creator` | 对每个 `apply_id` 调用 | DeepSeek 85 分制评分，幂等（已评分返回 `already_scored`） |
| 4 | `tk_send_feishu_card` | 仅 S/A 级 | 飞书交互卡片，D 级 `soft_rejected` 不发卡 |

### 评分体系

85 分制（v1，2.1 视频质量固定 0 分），4 维度 12 子项：

| 维度 | 满分 | 关键子项 |
|---|---|---|
| 商业带货能力 | 40 | 历史GMV(20) / GMV增长(10) / 成交效率(10) |
| 内容生产能力 | 15 | 视频质量(0,固定) / 内容稳定性(10) / 爆款能力(5) |
| 账号质量 | 15 | 粉丝质量(5) / 粉丝匹配(5) / 账号稳定(5) |
| 合作价值 | 15 | 品类匹配(5) / 合作意愿(5) / ROI潜力(5) |

等级：S(76-85) / A(64-75) / B(51-63) / C(34-50) / D(<34)
- S/A 级：发飞书卡片
- B/C 级：在 agent 响应中摘要呈现
- D 级：soft_rejected，不发卡片

### 数据库表

- `sample_requests` -- 样品申请记录（UPSERT by `apply_id`）
- `creators` -- 达人详情快照（UPSERT by `creator_oec_id`，7 天缓存）
- `creator_scores` -- 评分历史（append-only，每次评分一行）

### 依赖

- CloakBrowser（步骤 1-2 的浏览器操作）
- Postgres（全流程数据持久化）
- LLM/DeepSeek（步骤 3 评分，走 Bifrost 代理）
- 飞书（步骤 4 卡片发送）

## 2. IM 未回复自动回复定时任务

### 触发频率
每 1 小时执行一次。

### 单次上限
最多回复 30 个 Not replied 会话（`limit=30`）。

### 流程

```
tk_im_messages (auto_reply=true, filter=not_replied, limit=30)
  |
  ├── 1. 提取会话列表（React Fiber -> conversationId / unreply / unreadCount / userInfo）
  ├── 2. 持久化所有会话元数据到 tk_im_conversations（UPSERT by conversation_id）
  ├── 3. 对每个 Not replied 会话：
  │     ├── locator.click() 打开会话
  │     ├── 提取聊天历史（DOM + React Fiber -> messageId / serverId / createTime / content）
  │     ├── 持久化消息到 tk_im_messages（UPSERT by message_id，天然去重）
  │     ├── [auto_reply] DeepSeek 根据话术模板 + 聊天上下文生成回复
  │     ├── fill textarea + click Send 发送到 TK IM
  │     ├── record_sent_reply 记录已发送回复（synthetic ID 去重）
  │     └── mark_conversation_replied 更新 unreply=false
  └── 4. 返回结果（会话数 / 消息数 / 回复数 / 错误）
```

### 参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `filter` | `not_replied` | 只处理 Not replied 会话 |
| `grab_messages` | `true` | 点击会话提取完整聊天历史 |
| `auto_reply` | `true` | 抓取后自动生成回复并发送（定时任务模式） |
| `limit` | `30` | 单次最多处理 30 个会话 |

### 回复生成

LLM 复用 `LLM_BASE_URL` + DeepSeek（与样品评分相同的 Bifrost 代理），system prompt 内嵌 `docs/tmp/话术.md` 的 5 类场景模板：

| 场景 | 触发条件 | 话术要点 |
|---|---|---|
| 场景1 | 初次打招呼 / 对方简单回复（Hi/Ok/Ty） | 自我介绍 + 合作案 + WhatsApp |
| 场景2 | 对话中还没交换联系方式 | 请求对方 WhatsApp/Email + 问产品偏好 |
| 场景3 | 对方发了 WhatsApp | 引导对方加我们 WhatsApp（friend limit 话术） |
| 场景4 | 对方没加 Showcase / 没申请样品 | 引导加 Showcase + 申请样品 |
| 场景5 | 对方已申请样品 | 确认加急审核 + 引导 WhatsApp |

LLM 根据聊天上下文选择场景并**灵活改编**（非原样复制），回复 50-200 字符，包含联系方式（WhatsApp: +1-213-728-9088 / Email: yaya1109842375@gmail.com）。

### 数据库表

- `tk_im_conversations` -- 会话列表（UPSERT by `conversation_id`，含 `unreply` 标记）
- `tk_im_messages` -- 消息历史（UPSERT by `message_id`，天然去重）

### 去重机制

- **消息去重**：`message_id`（UUID）作为 PRIMARY KEY，UPSERT 天然去重
- **已发送回复去重**：发送后生成 synthetic ID（`sent-{uuid}`），下次抓取时真实 serverId 会 UPSERT 更新
- **会话去重**：`conversation_id` 作为 PRIMARY KEY，重复抓取只更新元数据

### 依赖

- CloakBrowser（浏览器操作：点击会话、填输入框、点发送）
- Postgres（会话 + 消息持久化）
- LLM/DeepSeek（回复生成，走 Bifrost 代理）

## 环境配置

定时任务依赖以下环境变量（在 `server-hermes/.env` 中配置）：

```bash
# CloakBrowser（浏览器工具需要）
CLOAKBROWSER_URL=http://cloakbrowser-manager:8080
CLOAKBROWSER_PROFILE_ID=<profile-id>
CLOAKBROWSER_TOKEN=<manager-token>

# Postgres（数据持久化）
DATABASE_URL=postgres://postgres:<password>@postgres:5432/tk_gateway

# LLM（评分 + 回复生成，走 Bifrost 代理）
LLM_BASE_URL=http://bifrost:8080/v1
LLM_API_KEY=<bifrost-api-key>
TK_SCORE_MODEL=opencode-go/deepseek-v4-flash

# TK Partner ID
TK_SAMPLE_PARTNER_ID=<样品市场partner-id>
TK_CREATOR_PARTNER_ID=<达人市场partner-id>

# 飞书（样品审核 S/A 级发卡片）
FEISHU_HOME_CHANNEL=<chat-id>
```

### 数据库初始化

首次部署需在共享 pg16 实例上创建 `tk_gateway` 数据库及 5 张表：

```sh
docker exec -i postgres psql -U postgres -f - < profile/plugins/tk-tpa/db/init-pg.sql
```

表清单：
1. `sample_requests` -- 样品申请记录
2. `creators` -- 达人详情快照
3. `creator_scores` -- 评分历史
4. `tk_im_conversations` -- IM 会话列表
5. `tk_im_messages` -- IM 消息历史

## Cron Job 配置

在线 Hermes Agent 中通过 cronjob 配置定时任务。两个任务的 prompt 必须自包含（cron 运行时无对话上下文）。

### 样品审核 cron

```
schedule: 30 9 * * *
prompt: |
  执行样品审核流程：
  1. 调用 tk_sample_requests(status=to_review, limit=50) 拉取待审核样品申请
  2. 对每条申请的 creator_oec_id 调用 tk_creator_detail 拉取达人详情
  3. 对每条 apply_id 调用 tk_score_creator 进行 85 分制评分
  4. 对 S/A 级达人调用 tk_send_feishu_card 发送飞书卡片
  汇总结果：申请数 / 评分数 / S/A 级数 / 发卡数 / 错误数
enabled_toolsets: ["tk-tpa"]
```

### IM 自动回复 cron

```
schedule: 0 * * * *
prompt: |
  执行 IM 未回复自动回复：
  调用 tk_im_messages(filter=not_replied, grab_messages=true, auto_reply=true, limit=30)
  抓取 Not replied 会话消息并自动生成回复发送。汇总结果：会话数 / 消息数 / 回复数 / 错误数
enabled_toolsets: ["tk-tpa"]
```

> 注意：样品审核每天 9:30 运行，IM 回复每小时整点运行。两个任务依赖同一个 CloakBrowser 会话，但时间基本不重叠。如果 IM 回复恰好在 9:00 运行而样品审核在 9:30 开始，IM 回复应在 30 分钟内完成。
