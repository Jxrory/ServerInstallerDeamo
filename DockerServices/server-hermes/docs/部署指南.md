# 部署指南

本文档记录 TK-TPA 插件（含 IM 自动回复功能）在远程服务器上的部署步骤。

## 环境信息

| 项目 | 值 |
|---|---|
| SSH 连接 | `ssh influence-os-server` |
| 项目目录 | `/home/ubuntu/ServerInstallerDeamo` |
| Hermes 目录 | `DockerServices/server-hermes` |
| env 文件 | `DockerServices/env/db.env` |
| compose 文件 | `DockerServices/server-hermes/compose.yml` + `DockerServices/compose/base.yml` |

## 容器架构

| 容器 | 用途 |
|---|---|
| `hermes-gateway` | Hermes Agent 主容器 |
| `postgres` | Postgres 16（tk_gateway 数据库） |
| `bifrost` | LLM 网关代理（DeepSeek） |
| `cloakbrowser-manager` | 浏览器自动化 sidecar |

## 部署步骤

### 1. 推送代码到远程仓库

在本地机器执行：

```bash
# 子模块
cd /Users/jxrory/Code/Project/TpaOs/hermes-plugin-tk-tpa
git add -A && git commit -m "feat: ..."
git push origin main

# 父仓库
cd /opt/Code/Project/ServerInstallerDeamo/DockerServices/server-hermes
git add -A && git commit -m "更新子模块 tk-tpa: ..."
git push origin main
```

### 2. 远程拉取代码 + 更新子模块

SSH 到服务器：

```bash
ssh influence-os-server
cd /home/ubuntu/ServerInstallerDeamo

# 拉取父仓库
git pull origin main

# 更新子模块（tk-tpa 插件）
git submodule update --init --recursive

# 验证
git log --oneline -3
git -C DockerServices/server-hermes/profile/plugins/tk-tpa log --oneline -3
```

### 3. 验证插件文件（容器内）

插件通过 bind-mount 映射到容器内 `/opt/data/plugins/tk-tpa/`，拉取代码后自动生效。验证：

```bash
docker exec hermes-gateway bash -c '
  ls /opt/data/plugins/tk-tpa/tools/im.py /opt/data/plugins/tk-tpa/internal/im_reply.py /opt/data/plugins/tk-tpa/schemas/im.py
  grep -c "auto_reply" /opt/data/plugins/tk-tpa/tools/im.py
  grep -c "场景" /opt/data/plugins/tk-tpa/internal/im_reply.py
'
```

### 4. 数据库初始化（首次部署）

如果 `tk_im_conversations` / `tk_im_messages` 表不存在：

```bash
docker exec -i postgres psql -U postgres -d tk_gateway -f - < \
  DockerServices/server-hermes/profile/plugins/tk-tpa/db/init-pg.sql
```

验证表存在：

```bash
docker exec postgres psql -U postgres -d tk_gateway -t -c \
  "SELECT tablename FROM pg_tables WHERE schemaname='public' ORDER BY tablename;"
```

应有 5 张表：`creator_scores` / `creators` / `sample_requests` / `tk_im_conversations` / `tk_im_messages`。

### 5. 重启 Hermes 容器

```bash
cd /home/ubuntu/ServerInstallerDeamo
HERMES_UID=$(id -u) HERMES_GID=$(id -g) \
  docker compose --env-file ./DockerServices/env/db.env \
  -f DockerServices/server-hermes/compose.yml \
  -f DockerServices/compose/base.yml \
  restart hermes-gateway
```

> 注意：启动命令必须带 `--env-file ./DockerServices/env/db.env`，否则 `DB_PASSWORD` 变量缺失会报错。

等待健康检查通过：

```bash
sleep 10
docker ps --format "{{.Names}}\t{{.Status}}" | grep hermes
# 应显示: hermes-gateway  Up X seconds (healthy)
```

### 6. 配置 Cron Job

Cron 配置存储在容器内 `/opt/data/cron/jobs.json`。

#### 查看现有 cron job

```bash
docker exec hermes-gateway python3 -c "
import json
with open('/opt/data/cron/jobs.json') as f:
    data = json.load(f)
for j in data['jobs']:
    print(f\"{j['name']} | {j['schedule_display']} | enabled={j['enabled']} | deliver={j.get('deliver','')}\")"
```

#### 添加/修改 cron job

通过 Python 脚本直接修改 `jobs.json`（参考 `docs/tmp/` 下的示例脚本），或通过 Hermes CLI 的 `cronjob` 工具。

线上当前配置的两个 cron job：

| 任务 | schedule | 说明 |
|---|---|---|
| TK Creator Review | `30 9 * * *` | 样品审核，每天 9:30 运行一次 |
| TK IM Auto Reply | `0 * * * *` | IM 自动回复，每小时整点运行一次 |

## 环境变量检查

所有环境变量在 `DockerServices/server-hermes/.env` 中配置，通过 compose `env_file` 注入容器：

```bash
docker exec hermes-gateway env | grep -E "DATABASE_URL|LLM_|CLOAKBROWSER|TK_|FEISHU"
```

应有以下变量：

| 变量 | 用途 |
|---|---|
| `DATABASE_URL` | Postgres 连接串（指向 tk_gateway） |
| `CLOAKBROWSER_URL` | CloakBrowser Manager 地址 |
| `CLOAKBROWSER_PROFILE_ID` | 浏览器 profile ID |
| `CLOAKBROWSER_TOKEN` | Manager Bearer token |
| `LLM_BASE_URL` | Bifrost 网关地址 |
| `LLM_API_KEY` | Bifrost API key |
| `TK_SCORE_MODEL` | 评分模型（deepseek-v4-flash） |
| `TK_SAMPLE_PARTNER_ID` | 样品市场 partner ID |
| `TK_CREATOR_PARTNER_ID` | 达人市场 partner ID |
| `FEISHU_HOME_CHANNEL` | 飞书接收频道 |

## 常见问题

### Q: 重启报 `DB_PASSWORD is required`

启动命令缺少 `--env-file`。必须带 `--env-file ./DockerServices/env/db.env`。

### Q: 插件工具找不到

检查 bind-mount 是否正确：`docker exec hermes-gateway ls /opt/data/plugins/tk-tpa/tools/`。

### Q: CloakBrowser 会话冲突

两个 cron job 都用 CloakBrowser，必须错开执行。当前配置：样品审核 `30 * * * *`，IM 回复 `0 * * * *`。

### Q: cron job 没执行

检查容器内 `/opt/data/cron/jobs.json` 中 `enabled=true` 且 `state=scheduled`。检查 `last_error` 字段。
